# Анализ проекта SQL-prototipo

Этот проект представляет собой прототип графического приложения (десктоп-клиента) на **C# Windows Forms** под целевую платформу **.NET 10.0 (windows)**. Оно предназначено для управления подключениями к базам данных и выполнения SQL-запросов.

---

## 📂 Структура проекта

Код приложения разделен на две папки:
1. `SQL prototipo` (с пробелом) — содержит весь рабочий исходный код.
2. `SQL-prototipo` (через дефис) — дублирующая папка с пустыми поддиректориями `Models` и `Services`. Вероятно, осталась после рефакторинга или инициализации.

### Ключевые файлы в `SQL prototipo`:

* **`Program.cs`** — точка входа в приложение, инициализирующая и запускающая `MainForm`.
* **`MainForm.cs`** и **`MainForm.Designer.cs`** — основная логика и дизайн формы. Содержит обработчики событий интерфейса.
* **`Models/ConnectionInfo.cs`** — модель данных для хранения настроек подключения (название, строка подключения, тип базы данных).
* **`Services/ConnectionManager.cs`** — сервис для сохранения, удаления и обновления списка подключений в файле конфигурации пользователя `user.config` в формате JSON.
* **`Services/DatabaseService.cs`** — сервис для взаимодействия с базой данных (получение списка таблиц, выполнение SQL-запросов).
* **`chinook.sqlite`** — встроенная демонстрационная база данных SQLite (на примере популярной тестовой базы Chinook).

## ⚙️ Функциональность приложения

1. **Управление подключениями**:
   * Пользователь может добавлять, редактировать и удалять подключения (CRUD).
   * Подключения сохраняются локально в файле `user.config` пользователя (в `AppData/Roaming/SQL_prototipo/...`).
   * В интерфейсе есть список подключений в виде `ListBox`, `ComboBox` для быстрого переключения и `TreeView` для отображения схемы.

2. **Работа со схемой данных**:
   * Двойной клик на подключение в `TreeView` загружает список таблиц этой базы данных.
   * Двойной клик на таблицу автоматически формирует шаблон запроса `SELECT * FROM [ИмяТаблицы];` в текстовом редакторе.

3. **Выполнение SQL-запросов**:
   * Имеется текстовый редактор `RichTextBox` для ввода SQL-запросов.
   * Кнопка **Execute Query** выполняет запрос асинхронно и выводит результат в таблицу `DataGridView`.
   * Кнопка **Load Tables** загружает схему таблиц текущего подключения.

## 🛠️ Замечания по архитектуре и коду (Code Review)

### 1. Жесткая привязка к SQLite (SQLite-only)
В интерфейсе (`cmbConnectionType`) пользователю предлагается выбор типов баз данных: **SQLite, SqlServer, MySQL, PostgreSQL**.
Однако в `DatabaseService.cs` логика работы жестко привязана к SQLite:
```csharp
using Microsoft.Data.Sqlite;
...
private SqliteConnection CreateConnection() => new SqliteConnection(_connectionString);
```
Кроме того, запрос списка таблиц использует специфичную системную таблицу SQLite:
```sql
SELECT name FROM sqlite_master WHERE type='table' AND name NOT LIKE 'sqlite_%';
```
При попытке использовать SqlServer, MySQL или PostgreSQL приложение выбросит исключение из-за несовместимости строки подключения или SQL-синтаксиса.

### 2. Прямая работа с XML `user.config`
В `ConnectionManager.cs` чтение и запись конфигурации реализованы вручную через парсинг XML-документа:
* Это рабочее решение, но оно чувствительно к структуре файла и пространству имен (`http://schemas.microsoft.com/2003/07/configuration`).
* Стандартные механизмы .NET (`System.Configuration` или `Microsoft.Extensions.Configuration`) были бы более надежными и требовали бы меньше кода.

### 3. Именование UI-компонентов
В коде формы `MainForm.Designer.cs` и `MainForm.cs` используются стандартные имена компонентов:
* `button1` (выполняет роль "Load Tables")
* `button2` (выполняет роль "Execute Query")
* `treeView1`, `dataGridView1`, `richTextBox1`
* `panel1`, `panel3`, `panel4`

*Рекомендация:* переименовать их в соответствии с их назначением (например, `btnLoadTables`, `btnExecuteQuery`, `tvDbSchema`, `dgvQueryResults`, `rtbSqlEditor`), чтобы улучшить читаемость и упростить поддержку проекта.

### 4. Неиспользуемые директории
Пустая папка `SQL-prototipo` засоряет структуру репозитория. Её можно безопасно удалить.

## 🚀 Предложения по развитию проекта

1. **Реализовать поддержку других СУБД**:
   * Выделить интерфейс `IDatabaseService` (или использовать ADO.NET абстракции `DbConnection`, `DbCommand` с помощью фабрик провайдеров `DbProviderFactories`).
   * Реализовать специфичные классы для работы с SQL Server (через `Microsoft.Data.SqlClient`), PostgreSQL (через `Npgsql`), MySQL (через `MySql.Data`).
2. **Улучшить SQL-редактор**:
   * Добавить подсветку синтаксиса для SQL-запросов в `RichTextBox`.
   * Добавить автодополнение названий таблиц и колонок.
3. **Улучшить обработку ошибок**:
   * Выводить более детальные сообщения об ошибках SQL-синтаксиса (например, с указанием позиции ошибки).
   * Добавить валидацию строки подключения перед её сохранением.
